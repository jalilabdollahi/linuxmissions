# Module 10: Archives and Compression

This module teaches packaging and unpacking data safely: tar member selection and excludes, each compressor's own tools (gzip, bzip2, xz, zip, cpio), splitting and rebuilding large files, checksums, and using `file`, `stat`, `du` and `df` to inspect and size an archive or a restore. Module 1 level 8 already covered "extract a tar.gz, create a tar.gz", so every level here goes beyond that. How I handled overlaps: this module is the home for checksum basics (`sha256sum`/`md5sum`, generating and `-c`). Module 14 verifies whole restored trees against manifests, module 16 checks authenticity with signatures, and module 26 uses them under time pressure. `du` and `df` appear here only for sizing an archive or restore, while module 17 ranks hotspots and module 14 covers sparse files and inodes. `split` here is byte-splitting binaries; module 25 covers line splitting and module 18 config splitting. `cpio` is taught here, and module 23 uses it for initramfs in a boot-recovery context. `backup-rotation` here is numbered shift rotation; module 14 does date-based GFS pruning, and modules 7 and 15 own logrotate. Three slugs are replaced: lsblk belongs to modules 14 and 24, a mount "notes" level needs root and checks nothing, and rsync's home is module 14.

| 9 | level-9-zip | intermediate | Last week's client hand-over `handover.zip` must be refreshed with this week's `handover/` dir, in place: changed files updated, deleted ones removed, symlink kept as a link. | `zip -r -FS` (filesync), `-u`, `-y`, `unzip -l`, `zipnote`/`unzip -z` | The member list and contents equal the current dir; `docs/latest` is stored as a symlink; the archive comment written at setup ("ACME hand-over, do not remove") is still there | Deleting and recreating the zip loses the archive comment; `-u` alone keeps deleted files; without `-y` the link becomes a copy |
| 10 | level-10-unzip | intermediate | A customer's `upload.zip`: put only its CSVs into `import/`, flat, without overwriting the newer `import/customers.csv`. | `unzip -l`, `-j`, `-n`, member patterns, `-d` | import/ has exactly the expected CSVs; the existing `customers.csv` is unchanged; no subdirectories were created | The CSVs sit at three different depths; the `-o` habit overwrites the newer file; a `README.csv.txt` decoy matches a careless `*csv*` |
| 11 | level-11-cpio | intermediate | Inspect an initramfs-style `initrd.img` (gzipped newc cpio): list the kernel modules it ships and extract only `etc/` into `initrd-root/`. | 12 | level-12-split | intermediate | The file share caps uploads at 5 MB (5,000,000 bytes). | 13 | level-13-cat-reassemble | intermediate | A backup arrived as `backup.part1` … `backup.part14` plus a stray `backup.part7 (copy)`. | 14 | level-14-sha256sum | intermediate | On a mirror box, verify `isos/` against `SHA256SUMS` (which also lists images you never downloaded), quarantine the mismatch, and write `SHA256SUMS.local` for what you keep. | `sha256sum -c`, `--ignore-missing`, `--quiet`, generating sums with relative paths | quarantine/ holds exactly the bad image; `sha256sum -c SHA256SUMS.local` passes inside isos/ and covers exactly the remaining files | Missing files make `-c` fail loudly; sums generated from the sandbox root contain `isos/` paths that don't verify from inside isos/ |

## Notes

- `cpio` (level 11) isn't in `docker/Dockerfile`, so add it. zstd is installed but not needed.
- Level 22 needs GNU tar (`--listed-incremental`), so it's Linux-only; macOS players would need `gtar`.
- Level 17 uses GNU `stat -c`, which is `stat -f` on macOS, and level 20 needs `xzgrep`/`bzgrep` (from xz-utils and bzip2). Level 9's `zip -FS` needs Info-ZIP zip 3.0, which is what the Dockerfile has.
- Levels 14/15: older macOS has only `shasum -a 256` and `md5`, so hints should mention that.
- Level 24's validator must plant a canary and check that nothing was written outside `$SANDBOX`. Setup builds the malicious tar with `tar --transform` or Python `tarfile`, so no real path is ever touched.
