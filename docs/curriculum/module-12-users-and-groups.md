# Module 12: Users and Groups

This module teaches the account databases (`/etc/passwd`, `shadow`, `group`, `gshadow`, `login.defs`, `skel`, `sudoers`, `subuid`), identity commands, password aging and locking, per-user and system-wide shell provisioning, and permissions for group collaboration. A non-root player can't change real accounts, so most levels work on copies of a server's `etc/` under `$SANDBOX` with small mock admin tools (`bin/useradd`, `usermod`, `gpasswd`, `chage`, `visudo -c`, `render-motd`) that edit those copies. `id`, `whoami`, `umask` and the permission levels run for real. How I handled overlaps: module 7 already created one user and wrote one sudoers rule, so here the work is audits and policy. Module 16 sudo-review finds dangerous command rules, while sudoers-audit here answers who can become root. Module 3 computes a umask value and module 16 hardens it; umask-basics here sets it inside a user's process for group collaboration. Module 9 owns startup-file order, and this module uses it for provisioning (skel, profile.d, safe rc files). Module 18 profile-d should take the editing and ordering angle. Module 24's `last` is login history; lastlog-audit here is about dormant accounts. Module 16 sgid-dir audits; shared-dir-policy here builds one. Two slugs are replaced: `su` can't be exercised without other accounts' passwords, and temp-file safety is module 16's temp-file-risks.

## Notes

- Mock tools live in `$SANDBOX/bin` and only edit `$SANDBOX/etc/*`. They are shared by levels 9, 11, 13, 18, 19, 22 and 24, and each objective must say "use the provided `bin/…`". Players may also edit the files by hand, since the validators check the resulting files, not which command was used.
- Real commands run as the player: `id`, `whoami` and `umask` (levels 3, 4, 10), and chmod, setgid and sticky bits on their own files (level 20). An optional default ACL in level 20 needs `setfacl` and ACL support on the sandbox filesystem, so it must not be required.
- Levels 11 and 17 use GNU `date -d`, which is `date -j -f` on macOS.
- Level 5 provides captured `/proc/<pid>/status` files, so it works on macOS too.
