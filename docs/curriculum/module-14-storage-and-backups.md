# Module 14: Storage and Backups

This module teaches disks, filesystems and backups without root. Disks are image files, which a normal user can partition (`sfdisk`), format (`mke2fs`), label (`e2label`), probe (`blkid -p`), inspect (`debugfs`) and image (`dd`). Mount configuration is practised on copies of `fstab`/`mountinfo`, because mounting needs root. File-level storage covers sparse files, hard and symbolic links, inodes and quotas. Backups cover rsync, manifests, verification, restores, hard-link snapshots and retention. How I handled overlaps: this module is the home for rsync (module 10's rsync-basics is replaced there) and for fstab basics (module 23 fstab-failures handles the boot-recovery side). Module 1 created a first symlink, module 23 audits broken links in recovery and module 26 has a link labyrinth; symbolic-links here is about relocatable relative links in a restored tree. Module 10 owns checksum basics; here they are applied to whole-tree manifests, while module 16 checks authenticity. Module 10's backup-rotation does numbered shifts; archive-prune here does date-based GFS. Module 15 cleanup-jobs schedules retention, while data-retention here implements the policy. Module 24 inspects the live machine's block devices and mounts; this module works offline on images and server captures. `snapshot-notes` is replaced, because LVM and btrfs snapshots need root and a notes level checks nothing.

## Notes

- Most of this module is Linux-only: `sfdisk`/`fdisk` on images, `blkid -p`, `mke2fs`/`dumpe2fs`/`e2label`/`debugfs`, `mountpoint`, `findmnt`, `/dev/shm`, sparse-file behaviour, and GNU `cp --sparse`, `ln -r`, `tar -S`, `find -printf`.
- `docker/Dockerfile` changes to verify or add: `rsync` (levels 10, 11, 20, 21), `e2fsprogs` (levels 2, 16, 17), and `fdisk` (Ubuntu ships `sfdisk`/`fdisk` in that package, separate from util-linux; levels 1, 8, 17, 24). Also confirm that `blkid`, `mkswap`, `findmnt` and `mountpoint` are present in the image.
- The game's safety filter blocks any command matching `mkfs` and `dd … of=/dev/sd*`. Level 2 must therefore tell the player to use `mke2fs`, and setup scripts must create filesystems with `mke2fs -F` on image files.
- Mocks: `setquota` and quota state for level 15; a `mountpoint` stub that the level 4 validator puts on PATH for the positive case only (the player's script must call `mountpoint` through PATH, and the objective has to say so); a slow `tar` stub for the level 9 validator.
- Levels 3, 5, 6 and 15 work on captures and config copies, so they need nothing beyond coreutils, plus `df`/`findmnt` for the `/dev/shm` part of level 6.
