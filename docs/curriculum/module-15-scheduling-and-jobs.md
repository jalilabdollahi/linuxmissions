# Scheduling & Jobs

This module teaches how work gets run later, repeatedly, or in the background: cron syntax and its traps (`%`, minimal `PATH`, run-parts naming, day-of-month OR day-of-week), `at`/`batch` queues, systemd timers, shell job control, detaching from the terminal, timeouts, locking, and log rotation driven by a schedule. It ends with fleet-wide schedule inventory and window planning. Overlap decisions: module 7 already writes one crontab line, one logrotate stanza and one `at` job, so here cron is the home topic and goes deeper (field semantics, environment, run-parts, missed runs), logrotate is *run* with a state file against a live writer (copytruncate), and `at` is about managing an existing queue. Module 26 `cron-mess` stays a wargame that mixes these skills. Module 13 `app-log-rotation` should take the "app reopens its log on SIGHUP / postrotate" angle so it does not repeat level 16 here. `watch` here waits for one event; module 17 `watch-loops` records a time series. Module 5 `subshells` already covers `&` + `wait` for parallel scripts, so the job-control levels here use job specs (`%2`), stopping/resuming and exit statuses instead.

## Notes

- **Mock tools:** `crontab` (stores in `$SANDBOX/spool/`, never the real user crontab; important on macOS), `at`/`atq`/`atrm`/`batch` (not in the reference image), and a mock "cron runner" that executes a crontab line with real cron semantics (`%`, env lines, minimal PATH). The validator-side cron expander (Python) should be one shared helper used by levels 1, 17, 18, 24.
- `systemd-analyze calendar` is present in the reference image and works as non-root without network (levels 7, 21). macOS has none: validators must fall back to the Python parser.
- `run-parts` (level 3) and `/proc/PID/status` SigIgn (level 8) are Linux-only; `last -x` in level 22 is a captured file.
- logrotate (level 16) is in the reference image; not on macOS by default.
- Job-control levels (9, 10, 11) depend on the engine's persistent interactive bash on a pty, where job control works. Ctrl-Z may not be forwarded by the engine; hints should offer `kill -STOP %1` as the reliable way.
- Level 13: `watch` is in the engine's full-screen list, but `watch -g ... && cmd` contains `&&`, so it runs in the captured shell. Test that it behaves.
