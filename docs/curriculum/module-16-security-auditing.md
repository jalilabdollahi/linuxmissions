# Security Auditing

This module teaches how to find and fix weaknesses on a host you are responsible for, working as an ordinary user: permission hardening with a security purpose, SSH server and key hygiene, verifying what you download, finding leaked secrets (files, environment, history, process arguments), unsafe scripts (temp files, PATH), risky sudo rules and service accounts, and finally a full audit and an incident clean-up. Overlap decisions: module 3 owns permission basics (chmod, octal, sticky bit, setuid search, umask arithmetic, world-writable fix), so levels 1–7 here always carry a security goal and a twist (ssh's strict-mode refusal, "never loosen" policies, capital `X`, auditing sticky bits, setgid only on directories, comparison against a baseline, a script that must set its own umask). Module 12 owns sudoers/account review and `secure-tempfiles`; here `sudo-review` is about privilege-escalation paths and `temp-file-risks` is the symlink attack, the home topic for temp-file security (module 12 should take the shared-`/tmp`-per-user angle). `ssh-config` here is the **server** `sshd_config`; module 18 `ssh-config-edit` is the **client** `~/.ssh/config`. Module 10 owns `sha256sum` basics; level 12 here is about a vendor SUMS file. Module 26 `secret-hunt` remains a wargame.

## Notes

- **Reference image gaps** (checked in `linuxmissions-test`): `ssh-keygen` (levels 9, 10) is missing, so add `openssh-client` to `tests/Dockerfile` (no network or daemon needed). `gpg` is missing but `gpgv` is present: level 11 uses pre-generated keyrings and signatures committed as fixtures and verified with `gpgv` only.
- No `sshd` binary, so level 8/24 effective-config checks use a Python parser that implements Include/first-match/Match semantics (shared helper).
- `visudo -cf file` works as non-root in the reference image (level 18).
- Linux-only: `/proc/PID/environ` and `/proc/PID/cmdline` (level 15). Level 15 must keep both workers' command lines containing the sandbox path so reset can kill them.
- Mock files: `passwd`/`group`/unit files (21), crontab spool (23, shared with module 15's mock).
- `chmod u+s`/`g+s` on own files works for a normal user, so levels 5/6 need no root. On macOS, setgid on directories is ignored by the kernel, but the bit is still set and checkable.
