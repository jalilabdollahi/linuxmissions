# Monitoring & Performance

This module teaches how to tell what a slow or failing box is doing: reading top/free/vmstat/uptime correctly, finding and targeting processes precisely, adjusting CPU and I/O priority, finding who holds files and sockets, spotting disk and inode hotspots, measuring log and error rates over time, and catching CPU churn, memory leaks and fd leaks by sampling instead of a single snapshot. Captured snapshots (with numbers randomised per setup) are used where the container's real values would be meaningless; live sandbox processes are used wherever the skill is about finding a real process. Overlap decisions: module 4 owns process basics (top-5 CPU, kill, start with `nice`, signals, zombies), so here `ps` sorts by memory/age, `nice` is about auditing and `renice` about fixing running processes, and `pkill` is about precise matching. Module 13 owns `journalctl` usage and `/proc/meminfo`/`cpuinfo` reading; level 18 here measures error *rates* from a JSON export, and level 3 is about the free vs available judgement. Modules 10/14 own `du`/`df` basics and inodes; here they are alert triage (inode exhaustion, sparse/apparent-size traps). Module 6 extracts ports from saved `ss` output, module 19 finds port owners, module 24 inventories listeners; level 14 here reads listen-queue pressure. Module 15 `watch-command` waits for one event; level 23 here records a time series.

## Notes

- **Linux-only:** `/proc/*` sampling (levels 13, 20–24), `ionice` (9: verified working as non-root in the reference image, class idle), `ss` queue semantics (14), diskstats format (5). macOS players should get a "Linux-only level" message.
- **Reference image gaps:** `lsof` and `iostat` are missing (hence REPLACE on 5 and 13). If `lsof` is added to `tests/Dockerfile`, level 13 can keep the old slug; the scenario is unchanged.
- Captured snapshots (1, 3, 4, 5, 6, 16, 18) must be generated per setup with random values, so answers can't be shared between players.
- Live levels must start every background process with the sandbox path in its command line and output redirected (authoring rule 5). Level 14's client and server, and level 20's spawner, must be stopped on reset.
- Level 2/21 memory: allocate with `python3 -c` and `bytearray`, touching pages so RSS is real; keep total under ~200 MB for CI.
