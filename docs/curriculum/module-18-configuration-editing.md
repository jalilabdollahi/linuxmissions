# Configuration Editing

This module teaches how to change configuration files safely and exactly: seeing hidden characters, in-place edits with backups, rewriting columns and sections, splitting and assembling configs, reviewing and applying diffs and patches, rendering templates without breaking literal `$` variables, editing INI/YAML/JSON structurally, and the quirks of real system files (`/etc/hosts`, `resolv.conf` under systemd-resolved, `~/.ssh/config`, `profile.d`, `/etc/aliases`, `/etc/exports`, `PS1`). It ends with a drift review and a multi-format repair. Overlap decisions: modules 2, 8 and 11 own `sed`/`awk`/`cut`/`paste` as text tools; here each is used on a config file with a config-specific constraint (address ranges, keep a backup, values containing `=`, building a one-line setting). Module 2 owns basic `diff`; here it is reviewing whitespace-noisy changes. Module 5 `heredoc` already renders one template from vars, so level 11 renders many environments from a CSV with values that break `sed`. Module 8 reads JSON with `jq`; level 14 edits it in place. Module 25 owns `csplit`; level 7 splits by content-derived names. `hosts-file` and `resolv-conf` here are about the file formats and who owns the file; module 19 uses them for diagnosis. `ssh-config-edit` here is the client config; module 16 `ssh-config` is the server. `aliases-file` is mail `/etc/aliases`, because module 9 owns shell aliases. Module 12 owns `/etc/profile` and `.bashrc`; level 18 here is about writing an idempotent drop-in.

## Notes

- **Reference image gaps:** `envsubst` (level 10, package `gettext-base`) and `ssh` (level 17, `ssh -G` needs `openssh-client`) are missing; the YAML validator (13, 24) needs `python3-yaml`. Add these to `tests/Dockerfile`. All three work offline.
- **Mocks:** `newaliases` (19), `exportfs -v` (20), a "resolved regenerate" script (16), `app --check-config` and the app server (24).
- `sed -i` differs between GNU and BSD (`-i.bak` works on both; `-i ''` is BSD-only). Hints for 3/16 should use `-i.bak`.
- Level 21 needs bash ≥ 4.4 for `${PS1@P}` in the validator (macOS system bash 3.2 lacks it; use the Homebrew bash or mark Linux-only).
- Levels 2 and 22 are about interactive tools (less, vi); the validators check only the answer or result, which is accepted. Hint 3 should still show the in-tool way.
