# Package & Release Ops

This module teaches how Debian/Ubuntu packaging works and how releases are shipped and undone: searching, installing specific versions, remove vs purge, index updates, kept-back upgrades, candidates and pins, holds, querying and verifying the dpkg database, repository keys and sources, then release engineering: version ordering, semver bumps, release notes, artifact layout, manifests, dependency impact, config reloads, atomic rollback and promotion gates. Everything runs as a normal user and offline. Real `apt-cache`, `apt-get -s` (simulate), `dpkg-query`, `dpkg --set-selections`, `dpkg -V` and `dpkg-deb` all work as non-root when pointed at a sandbox dpkg database and a local `file:` repository (`APT_CONFIG` / `--admindir`, checked in the reference image). Only the final "install/remove" step that dpkg would do as root is a mock (`sapt`) that runs the real `apt-get -s` and then applies its plan to the sandbox status file. Overlap decisions: module 10 owns tar/checksum basics; here level 18 is a reproducible release tarball and level 19 is deploy verification, while module 14 `backup-manifests` covers backups and module 16 `sha256-verify` covers vendor downloads. Module 16 `cve-version-triage` uses `dpkg --compare-versions` for security; level 15 here owns version-ordering rules. Module 26 `release-rollback` and `package-panic` remain wargames that mix these skills.

## Notes

- **Sandbox apt:** a shared fixture creates `$SANDBOX/apt/` (status file, lists, cache, `sources.list.d`, `preferences.d`) and an `apt.conf` with `Dir::State::status`, `Dir::State::Lists`, `Dir::Cache`, `Dir::Etc` and `Debug::NoLocking=1`; levels export `APT_CONFIG` so real `apt-cache`/`apt-get -s`/`apt-get update` work against a local `file:` repo. The repo's `Packages`/`Release` files are generated at setup (`dpkg-deb --build` works as non-root for real `.deb`s, needed in 21).
- **Mock:** `sapt install/remove/purge` runs the real `apt-get -s` and applies the resulting plan to the sandbox status file (levels 2, 3). The pricer daemon and app servers (22, 23) are small Python HTTP servers on 127.0.0.1.
- **Signed repo fixtures:** `gpg` is not in the reference image, only `gpgv`. Pre-generate keys, `InRelease` signatures and `.sig` files once and commit them (11, 24). Don't use `Valid-Until` in Release files, or the fixtures will expire.
- Linux-only (Debian tooling): every apt/dpkg level (1–12, 14 for the installed version, 15, 20, 21, and 24's version gate). Levels 13, 16–19, 22 and 23 work on macOS if hints avoid GNU-only flags (`tar --sort` needs GNU tar; `find -printf` is GNU).
- Checked in the reference image as a non-root user: `apt-cache policy` with custom Dir options, `apt-get -s` with a custom status file, `dpkg --admindir --set-selections`, `dpkg -V`, `systemd-analyze calendar`, `visudo -cf`.
