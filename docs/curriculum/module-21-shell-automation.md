# Shell Automation

This module teaches how to write bash scripts that run unattended (from cron, CI or a teammate's terminal) and still behave correctly: argument handling, exit codes, loops over real input, failure handling, cleanup and reuse. In every level the player writes or fixes a script. The validator then runs that script with several inputs, including spaces in names, missing arguments and failures injected through small mock tools. Overlap decisions: module 5 (handwritten) owns first-script basics such as `$1`, a simple `if`, a rename loop, defining a function, a template heredoc and adding `set -euo pipefail`. Module 9 owns how the interactive shell expands things: quoting, `[ ]`, `case`, here-docs and here-strings, `$( )`, `source` and shell options. For the slugs that overlap those modules (case-esac, test-operators, command-substitution, heredoc, set-e, pipefail, modules-source), this module teaches how each one *fails in an unattended script*. It does not reteach the syntax. Level 24 uses module 15's `flock` and `timeout` inside a script as building blocks.

## Notes
- Mock tools that setup ships: `upload` (3, 6), `remote` (8), `git` (14), `mock_pg_dump` (20) and a `df` capture (9). Each mock logs its argv or mode so the validator can check how it was called.
- Level 1's validator needs python3 (already in the image) to exec the helpers without the shell's ENOEXEC fallback.
- Linux-only or GNU-specific: `date -d` (7), `mapfile`, `BASH_XTRACEFD` and associative arrays need bash ≥ 4 (macOS ships bash 3.2), `readlink -f` (22), `flock` (24).
- Level 17's TERM test and level 24's timeouts take a few seconds. Keep sleeps short and configurable through env vars so the test runner stays fast.
