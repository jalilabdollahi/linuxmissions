# Data Processing

This module teaches how to turn messy real-world exports (CSV from Windows tools, fixed-width bank files, access logs, epoch timestamps) into correct reports and reconciliations, mostly with awk, sort, join and friends. Overlap decisions: module 11 owns the basic syntax of cut, paste, join, comm, sort, uniq, tr, sed and awk. Modules 2 and 8 (handwritten) already cover top talkers, extracting fields 1 and 3, an awk sum per category and `column -t`. Module 22 is the home for working with whole datasets: headers, numeric types, statistics, pivots, dates and reconciliation. Where a slug repeats a module 11 tool, this module takes a different angle:
- uniq-count counts *consecutive runs*, not sorted totals.
- cut-delimiters works on a fixed-width file.
- paste-merge reshapes records that span several lines.
- join-keys is an outer join with collation pitfalls.
- comm-diff is a three-source reconciliation with normalisation.

Splitting by line count or pattern belongs to module 25 (split, csplit); records-split here splits *by field value*. Time zones and multi-service log correlation are left to wargame 29 (log-maze).

## Notes
- Validators may use python3 (`csv`, `json`) to parse the player's output for levels 18 and 23; python3 is already in the reference image.
- GNU/Linux-specific: `date -d` and `date -u -d @N` (11, 12), gawk `strftime` with the UTC flag and `FPAT` (11, 18), `sort -g` (5). The BSD tools on macOS behave differently.
- Level 22's hidden dataset should be generated in validate.sh with a fixed seed so the expected answer is reproducible.
