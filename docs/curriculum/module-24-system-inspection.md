# System Inspection

This module teaches how to answer "what is this machine, and what is it doing?" from the system itself: `uname`, `/proc` and `/sys`, the login records, sockets, kernel parameters, resource limits, cgroups and namespaces. Some levels inspect the live sandbox machine: setup starts processes or listeners, and the validator computes the answer from live `/proc` at check time. Others use captures from a production host, wherever a container can't show the real thing (PCI and USB devices, cgroup trees, namespaces, other hosts' meminfo). Overlap decisions:
- Module 24 owns reading the live system. Module 23's uname-a level does fleet reboot detection instead.
- Module 13 reads `/proc/cpuinfo` and `/proc/meminfo` for basic facts. Here cpu-info is about topology for licensing, and mem-info is about where memory went.
- Modules 10 and 14 own lsblk and blkid basics; block-devices here is "find the right disk to pull".
- Modules 6, 17 and 19 parse `ss` for ports. Here open-ports maps a socket to a lying process, and listening-services maps sockets to systemd units.
- Module 9 owns your own shell's environment; env-print reads *another process's* environment.
- Module 10 introduces `file`; file-types is a forensic sort.
- Module 17 teaches lsof; tempdirs recovers deleted-but-open data.

## Notes
- Live levels (2, 6, 14, 15, 19, 22, 24) depend on `/proc` and are Linux-only. Background processes need the sandbox path in their command line (rule 5) and redirected output.
- Levels 3 and 5 need binary `utmp`/`wtmp` fixtures. Generate them with `utmpdump -r` in setup, or ship pre-built files; the record format is the same on x86_64 and aarch64. Check that `utmpdump` and util-linux `last` exist in the ubuntu:24.04 image. Debian is moving `last` to wtmpdb.
- Level 15 binds only to 127.0.0.1 / ::1 (no network use). Without root, `ss -p` shows owners only for your own processes, which is enough here.
- PCI, USB, cgroups, namespaces and other hosts' memory use captures, because what a container can see varies by host. Generate the captures from real machines and keep them in the level folder.
