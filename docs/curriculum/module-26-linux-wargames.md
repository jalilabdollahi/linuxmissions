# Linux Wargames

The finale. Each level is an on-call incident that combines skills from several earlier modules. The objective states only the symptom and the required end state, never the steps, so the player has to find the problem. Most incidents have more than one cause, and fixing the obvious symptom alone never passes. Levels 1–11 are advanced warm-ups with one main cause plus a trap. From level 12 on they are expert, with multiple causes, live processes and decoys, and levels 26–30 are the hardest in the game. Every validator checks the final state of the system (files, modes, running processes, mock-service state, a health check against localhost), not the commands that were typed. The "skills" column starts with the earlier modules each level draws on. Each wargame reuses a skill in a new combination. None repeats a single level: for example, wargame 14 is about hard links vs symlinks and relocation, not module 23's offline-root link audit, and wargame 16 attributes disk writes, not the listening port of module 24.

## Notes
- Mocks and simulators shipped by setup: `relay` (21), `cron-sim` (12), `ip` with route-get logic, best written in python3 (24), `boot-sim` (28), `deploy-sim` (17), `systemctl` and `appctl` (10, 23, 30), and a background "cron loop" (30). The live levels (2, 8, 9, 16, 23, 26, 30) start background processes, which must have the sandbox path in their command line.
- Level 15 needs `envsubst` (gettext-base). Check that it is in the image (module 18's envsubst level needs it too). Level 5 needs a filesystem with ACL support, plus the `acl` package, which is already installed.
- Level 22 relies on GNU tar's incremental format. Levels 2, 8, 9, 16, 23, 26 and 30 depend on `/proc`, signals or `flock` and are Linux-only.
- Level 27 should not need `strings` (binutils is missing), unless binutils is added for module 25; `grep -a -o` and `base64 -d` are enough there.
