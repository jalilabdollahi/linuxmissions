# Who Owns This File

## Why it works
`dpkg -S PATH` searches the file lists of all installed packages (`/var/lib/dpkg/info/*.list`)
for that exact string. On a merged-/usr system `/bin`, `/sbin` and `/lib` are symlinks to
`/usr/bin` and so on, and packages record the `/usr/...` name, so `dpkg -S /bin/dbtool`
finds nothing while `dpkg -S /usr/bin/dbtool` does. `readlink -f` resolves the link first.
Files in `/usr/local` (hand-installed) and files generated by a script or at runtime appear in
no list: for those the honest answer is `none`.

## Common mistakes
- Reading "no path found" as "unowned" without trying the resolved path.
- Believing that a file inside a package's config directory belongs to that package: a
  `generated.conf` created by a script is not in its file list.
- Using `dpkg -S dbtool` (a pattern): it matches every path containing the word.

## Next step
`dpkg -L PACKAGE` lists everything a package owns, `dpkg -V PACKAGE` checks those files
against their checksums (module 20 level 21), and `apt-file search` finds the owner of a file
in packages you have not installed.
