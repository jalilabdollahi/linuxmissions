`ip rule` lists the policy rules (lowest number first), `ip route show table all` all tables, and `ip route get DST from SRC` asks which route a flow would really take (PLAN.md lists 12 of them to check). A lookup that finds no route in a table continues with the next rule. A /24 beats a /16 regardless of metric; two routes with the same prefix and metric are a tie you should not leave to chance. Routes are added with `ip route add PREFIX via GW dev DEV table NAME` and removed with `ip route del`, rules with `ip rule del priority N`. Compare what you get with PLAN.md after each change.
